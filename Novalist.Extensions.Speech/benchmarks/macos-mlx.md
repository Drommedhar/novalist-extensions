# Qwen3-TTS on MLX: M5 Pro

Measured 2026-09-09 on Apple M5 Pro, 48 GiB unified memory, macOS 26.5.2,
ARM64 Python 3.12.12. Full measurements, versions and checkpoint revisions are
in [macos-mlx.json](macos-mlx.json). All prose is synthetic benchmark text.

## Result

| Backend | Warm synthesis | Audio duration | Compute / audio second |
| --- | ---: | ---: | ---: |
| PyTorch MPS BF16 | 15.74 s | 7.44 s | 2.116 |
| MLX BF16, matched cloning settings | 7.69 s | 7.44 s | 1.033 |

The final short-passage comparison ran sequentially, three generations per
backend, with the first excluded from the mean. MLX was **2.05× faster**.
Imports, model loading, and WAV writing are excluded; Metal work is synchronized
before ending each timing. The same reference WAV, exact German transcript,
passage, seed 42, temperature 0.9, top-k 50, top-p 1.0, repetition penalty 1.05,
and 8192-token ceiling were used. Prompt preparation is reported separately
for PyTorch; MLX's first generation includes its reference preparation.

Longer exploratory runs produced 28.32 seconds of audio in 29.02 seconds on
MLX, versus 29.36 seconds in 55.30 seconds on PyTorch. These used only one warm
repeat and were separated in time. Voice design averaged 10.22 seconds for
10.16 seconds of audio. Treat these as illustrative, not a stable guarantee.

MLX reported about 4.63 GB active allocations and 10.19 GB peak for the short
non-streamed passage. PyTorch reported 4.23 GB active and 8.58 GB driver
allocations; driver and MLX peak figures are different metrics and cannot
establish a peak-memory improvement.

## Quality and backend behavior

The conversion adds **no quantization**. Direct byte comparisons verified every
weight in Base (480 tensors), VoiceDesign (404 tensors), and each speech codec
(496 tensors each). The only layout changes were 38 Base Conv1d transposes;
all dtypes and values were otherwise identical to the original checkpoints.
Main weights are BF16; codec weights are FP32 in the stored checkpoints.

The public mlx-audio cloning API forces a repetition penalty of at least 1.5.
The production adapter therefore calls the pinned 0.5.3 ICL method directly
with 1.05 to preserve Novalist's existing settings. Temperature is also shared
between the talker and code predictor, matching the current 0.9/0.9 behavior.
Each reference gets its own prompt cache to avoid upstream cache-key collisions.

Generated audio is finite and nonempty. A small automated Whisper transcription
check recovered the expected prose but also produced suspicious repeated
suffixes on several clips, including the PyTorch baseline. It is insufficient
to certify perceptual equivalence. Same weights and settings avoid a deliberate
quality reduction; numerical differences between runtimes can still change
pronunciation, pacing and sampled audio. Seeds are repeatable within each
backend, not interchangeable across them. Listening tests remain necessary
before claiming identical perceived quality.

Streaming was benchmarked separately. It reduced MLX peak allocations to about
5.2 GB and delivered an initial chunk in roughly 0.4 seconds on the short
passage. A later long streaming run was much faster than the earlier tests,
so those measurements should not be combined into a single speedup claim.
**Production still returns complete passages.** Integrating intra-passage
playback is a separate host/protocol change.

## Reproduction

Create an isolated environment from `python/requirements-macos.txt`. The
benchmark environment's exact resolved versions are recorded in
[mlx-requirements.lock.txt](mlx-requirements.lock.txt); that benchmark environment
does not include the production-only librosa speed adjustment dependency.
Download the two `mlx-community/Qwen3-TTS-12Hz-1.7B-*-bf16` checkpoints with `hf`
into a dedicated cache. For exact reproduction, select the revisions in JSON
using `hf download --revision` and the benchmark's `--revision` option.

From the extension repository root, using the same reference WAV for both:

```sh
MLX_PYTHON=artifacts/speech-mlx/venv/bin/python
"$MLX_PYTHON" Novalist.Extensions.Speech/benchmarks/benchmark_mlx.py \
  --cache artifacts/speech-mlx/models --output artifacts/speech-mlx/repeat \
  --reference artifacts/speech-m5/design-fp32/design-0.wav --api matched --runs 3
```

The reference is generated by `python/benchmark.py --mode design --dtype float32`
with German defaults. Run that script with the PyTorch environment and original
Qwen cache; then use its `--mode clone --reference ... --runs 3` for the baseline.
For longer passages add `--passage long` to the MLX command and pass that exact
text to the PyTorch script through `--text-file`. Run GPU cases sequentially.
`compare_checkpoint_weights.py` accepts `--original`, `--mlx` snapshot directories
and `--output` to reproduce the full weight comparison.
